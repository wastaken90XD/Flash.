## 2. Issues Found & Fixed During TSD 3.14 Re-Audit

1. **Frame-1 button hit-testing & action ordering (`crates/swfr-player/src/lib.rs`):**
   - `Player::run_frame` previously called `stage.update_pointer` *before* `stage.step_frame`. On the first frame after `retro_load_game`, the display list was still empty when pointer hit-testing ran; furthermore, when a button click triggered `gotoAndStop(2)`, the subsequent `stage.step_frame` in the same `retro_run` immediately stepped the timeline again. Fixed by executing `stage.step_frame` first to populate/advance the display list, and then processing `stage.update_pointer` and any triggered button actions.
2. **Newly placed `DefineSprite` double-stepping on placement (`crates/swfr-scene/src/lib.rs`):**
   - `step_timeline_one_frame` previously stepped all child sprites found in `timeline.display` after executing the parent's frame tags, including sprites placed during that same frame (`frame0_executed = true`), causing newly placed sprites to jump to frame 1 on their placement frame. Fixed by snapshotting `existing_depths` prior to executing the parent frame's tags so only pre-existing child sprites advance on that tick.
3. **Recursive character definitions inside `DefineSprite` (`crates/swfr-scene/src/lib.rs`):**
   - Real-world SWFs occasionally nest character definition tags inside `DefineSprite`. Updated `Stage::register_definitions` to recurse into `Tag::DefineSprite` tag streams.
