## 2. Issues Found & Fixed During TSD 3.14 Re-Audit

1. **End-to-end `SharedObject.getLocal` -> `RETRO_MEMORY_SAVE_RAM` wiring (`crates/swfr-avm1/src/lib.rs`, `crates/swfr-player/src/lib.rs`, `crates/swfr-libretro/src/{state.rs,ffi.rs}`):**
   - `SharedObject.getLocal` previously returned an in-memory object whose `flush()` method was a no-op and `retro_get_memory_size(RETRO_MEMORY_SAVE_RAM)` returned `0`. Implemented full `"SWFS"` + version (`1`) + length + CRC32 binary serialization into a 64 KiB (`65,536 B`) `SAVE_RAM` buffer in `Avm1` and `Player`, wired `retro_get_memory_data(RETRO_MEMORY_SAVE_RAM)` and `retro_get_memory_size(RETRO_MEMORY_SAVE_RAM)` to the `CoreState::save_ram` buffer, and added lazy synchronization on the first `retro_run` after `retro_load_game` so frontends that populate `RETRO_MEMORY_SAVE_RAM` after `retro_load_game` restore persisted `SharedObject` data seamlessly.
2. **AVM2 warning emission timing (`crates/swfr-player/src/lib.rs`):**
   - Emitted the once-per-load AVM2 (`ActionScript 3.0`) diagnostic notice on frame 1 in `Player::run_frame` in addition to `retro_load_game` so frontends or tests that inspect `retro_log_printf_t` during `retro_run` also observe the warning once.
